## 1. 目标

- **P0（多租户骨架）**：
  - 开发环境一键启动。
  - 平台可以开通租户；员工可以登录。
  - 按角色控制功能权限，按租户隔离数据（PostgreSQL RLS），按归属控制客户可见性（DataScope）。
  - 提供控制台和运营后台的骨架，CI 全绿。
- **P1（Web 客服核心）**：接入 OpenIM，完成访客 Widget、会话与路由、坐席工作台、转接与客户转移。P0 完成后再细化任务。

## 2. 工程约定

- **目录**：
  - `backend/`：FastAPI 后端。
  - `frontend/`：pnpm workspace，包含 `apps/console`、`apps/platform-admin`、`packages/api-client`。
  - `deploy/compose/`：开发环境。
- **后端**：
  - Python 3.12，用 uv 管理依赖。
  - FastAPI、SQLAlchemy 2（async + asyncpg）、Alembic。迁移手写，因为 RLS 策略要用 SQL 表达。
  - pydantic-settings（环境变量前缀 `EDP_`）、argon2-cffi、PyJWT、uuid-utils（UUIDv7）。
  - 测试用 pytest + httpx，代码检查用 ruff + mypy。
- **数据库角色**：

  | 角色 | 用途 | RLS |
  |---|---|---|
  | 所有者（开发环境为 `postgres`） | 执行迁移 | — |
  | `edp_app` | 员工请求（租户内） | 受租户隔离策略约束 |
  | `edp_platform` | 平台运营、租户开通 | 通过专用策略访问全部行 |

- **租户上下文**：
  - 每个事务开始时执行 `set_config('app.tenant_id', <租户ID>, true)`，由 SQLAlchemy 的 `after_begin` 事件自动完成。
  - RLS 策略使用 `app_current_tenant()`（等价于 `NULLIF(current_setting('app.tenant_id', true), '')::uuid`）。
  - 没有设置租户时查询返回空（fail-closed）。
- **跨租户引用**：租户表之间的外键使用 `(tenant_id, id)` 复合外键，从数据库层面禁止引用其他租户的行。
- **接口**：
  - `/api/v1/*` 面向租户员工，`/platform/v1/*` 面向平台运营。
  - 错误统一为 `{"error": {"code": "...", "message": "..."}}`。
- **令牌**：
  - 员工：Access Token（15 分钟）+ Refresh Token（7 天，httpOnly Cookie，每次刷新都轮换；检测到重复使用时吊销整组）。
  - 平台：独立密钥签发的 Access Token（2 小时）。
- **前端**：
  - Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus（中文）。
  - API 类型由后端导出的 `openapi.json` 经 openapi-typescript 生成，请求用 openapi-fetch。
- **提交**：每个任务独立提交，提交前本地跑通 lint 和测试。

## 3. P0 任务

| # | 任务 | 主要产出 | 验证 |
|---|---|---|---|
| T1 | 仓库骨架与开发环境 | `.gitignore`、`.editorconfig`、`Makefile`；`deploy/compose`（PostgreSQL 17 + pgvector、Redis，初始化数据库角色） | `make dev-up` 后容器健康 |
| T2 | 后端工程骨架 | `pyproject.toml`、应用工厂、配置、错误处理、健康检查 | ruff、mypy、健康检查测试 |
| T3 | 数据库层与租户隔离 | 模型、Alembic `0001`（表、复合外键、RLS 策略、授权）、租户会话 | RLS 测试：未设租户返回空；只能看到本租户；写入其他租户被拒；跨租户外键被拒；所有带 `tenant_id` 的表都已启用并强制 RLS |
| T4 | 认证 | 员工登录/刷新/登出、`/me`；平台登录 | 登录成功/失败、停用租户、停用员工、刷新轮换、重复使用检测、两类令牌互不通用 |
| T5 | 权限与数据范围 | 权限点、默认角色、`require_permission`、客户接口（列表/创建/详情） | 坐席只看自己的客户；管理员看全部；跨租户按 ID 访问返回 404；越权分配归属返回 403 |
| T6 | 租户开通与运营接口 | 开通服务（租户 + 默认角色 + 管理员）、租户列表/停用、CLI（创建平台管理员、开通租户、导出 OpenAPI） | 开通、重复代码 409、停用后该租户令牌失效 |
| T7 | 员工管理 | 员工列表/创建、角色列表 | 管理员可创建坐席；坐席无权创建 |
| T8 | API 客户端 | `openapi.json` 导出、`packages/api-client` | 生成的类型与后端一致（CI 检查漂移） |
| T9 | 控制台骨架 | 登录、布局、按权限显示菜单、客户与员工页面 | vitest（菜单过滤、令牌刷新重试）、类型检查、构建 |
| T10 | 运营后台骨架 | 登录、租户列表、开通租户、停用/启用 | 类型检查、构建 |
| T11 | CI | GitHub Actions：后端（PostgreSQL 服务容器）、前端、OpenAPI 漂移检查 | 推送后流水线通过 |
| T12 | 端到端验收 | README 快速开始；本地启动全套服务，用浏览器验证 P0 验收标准 | 截图：两个租户互相隔离，管理员和坐席看到的菜单不同 |

**P0 验收标准**（来自设计文档 §21）：

1. 可以一键启动开发环境。
2. 可以开通两个租户，且互相看不到对方的数据。
3. 不同角色登录后看到不同的菜单。

**P0 并行事项**（不在代码范围内，需要你们推进）：

- 注册企业微信服务商，提交代开发应用模板审核。
- 大模型登记/备案评估。
- OpenIM 商业授权询价。

## 4. P1 里程碑（P0 完成后细化为任务）

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 OpenIM 集成 | 开发环境接入 OpenIM；`im-client` 封装；用户与 Room 开通；发送后回调入库；按 seq 对账 | 访客消息可靠入库，回调丢失后可以补录 |
| M2 会话与路由 | Session 状态机、路由策略、技能组、排队与分配、坐席状态 | 排队、分配、超时处理符合设计 §11.3 |
| M3 访客 Widget | 嵌入脚本、iframe、匿名/实名访客、文件、满意度、留言 | 在测试页面嵌入后可以与坐席实时对话 |
| M4 坐席工作台 | 会话列表、聊天区、客户面板、快捷话术 | 历史走 API、增量走 IM，消息不重复 |
| M5 转接与归属 | 会话转接（接受/拒绝/超时）、客户转移、归属历史 | 转接后新坐席能看到完整历史，旧坐席不可见 |
| M6 管理与计量 | 技能组、渠道、路由策略配置；基础报表；用量计量；对象存储（MinIO 社区版镜像的维护状态需评估，必要时换成其他 S3 兼容存储） | 管理员可以完成渠道配置；用量按日汇总 |

## 5. 风险与说明

- **开发环境**：OpenIM 在 P1 M1 再接入开发环境。P0 只包含平台自身的依赖，避免引入未验证的配置。
- **平台运营令牌**：P0 不做刷新，页面刷新后需要重新登录；P1 再补充。
- **敏感字段加密**：租户级数据密钥和敏感字段加密（如客户手机号）在 P1 实现；P0 的客户模型不包含敏感字段。
