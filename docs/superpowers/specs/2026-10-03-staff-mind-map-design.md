# 员工思维导图：方向分支新增

## 用户已确认的目标

将 `/staff` 的员工组织图改为可扩展的思维导图。企业名称为根卡片；支持多个管理员；企业和每张员工卡片均可向左、向右、向下新增员工卡。创建时独立选择角色、页面和权限。卡片连线只用于展示，不建立管理归属，不影响权限计算。

成功标准：从任一卡片选择方向并创建员工后，新卡片出现在该方向且与来源卡片连接；刷新、退出重新登录或换电脑后关系仍存在。保留现有员工编辑、启停、密码重置、客户交接和角色管理。

## 交互

1. 有 `staff:manage` 权限的用户在企业卡片和员工卡片上看到三个按钮：`← 新增`、`新增 →`、`↓ 新增`。只读用户可以查看图形，不能创建。
2. 点击打开现有“新建员工”对话框，顶部明确显示“在 王凯 左侧新增员工”等来源与方向；企业来源使用企业名称。
3. 表单继续包含账号、姓名、初始密码、角色和页面权限，不从来源卡片继承角色或权限。默认角色仍为客服，允许自行调整。
4. 取消或创建失败时不增加节点、不保存布局；创建成功后关闭对话框、重新读取数据并定位新卡片。
5. 原有顶部“新建员工”按钮继续可用，创建后使用默认布局。

## 数据与接口

推荐在员工记录上新增可空的布局来源和方向字段，而不是保存在浏览器本地；这样布局可跨浏览器同步，并与员工创建在同一事务中完成。

- `diagram_parent_id`：来源员工 ID；企业根来源用 null。
- `diagram_direction`：`left`、`right`、`down`；null 表示该员工没有自定义布局，使用既有分层展示。
- 企业根也可以拥有三个方向的分支：parent 为 null、direction 有值。
- 字段只参与图形渲染，不参与 `Principal`、角色权限、客户可见范围或员工管理权限。

增加数据库迁移，已有员工字段默认 null。扩展 `StaffCreate`、`StaffOut` 和前端生成的接口类型。创建时，后端检查来源员工属于当前租户且存在，方向必须合法；填写来源却未填写方向则拒绝。不增加移动已有卡片、重新挂接节点或删除员工功能，因此新员工只引用已有来源节点，不会形成循环。

后端同时记录创建员工与布局字段；角色检查、权限防越权、账号唯一性、席位限制和审计继续执行。新卡片不能因连在管理员下面而自动获得管理权限。

## 图形布局

- 初始未设布局的员工继续按“企业 → 并列管理员 → 企业员工”展示。
- 显式方向分支优先按保存的来源和方向绘制；不重复显示员工。
- 左侧、右侧分支分别位于来源左右，下方分支位于来源下方；同方向多个分支按创建时间和 ID 稳定排序，展开占位并避免卡片重叠。
- 连线连接卡片边缘，不能穿过卡片正文。需要测量卡片尺寸并在图形区域或卡片大小变化后重算位置。
- 图形区域允许双向滚动；保留键盘可达的新增与员工操作按钮。小屏也能通过滚动查看全部卡片。
- 员工停用后保留节点与分支，显示停用状态；没有员工时仍能从企业卡片创建。
- 对异常或不可见来源节点，将员工放入企业下的备用分支，保证每位可见员工均有且仅有一张卡片。

## 验证与交付

- 后端：正常创建三个方向分支；非法方向、来源不存在、跨租户来源被拒绝；创建失败没有残留员工或布局；原员工创建兼容；布局不改变角色与权限。
- 前端：从企业和员工新增三个方向；取消不新增；错误保留表单；多管理员、多层分支、同方向多个员工、空数据、停用员工、异常来源均正常展示。
- 布局测试：每人只出现一次，三个方向正确，卡片边界不相交，重复计算稳定。
- 检查前端测试、类型、构建与 lint；更新现有员工页面验收选择器并验证真实界面。
- 本机启动与数据库迁移由用户自行执行，提供必要步骤；不替用户启动应用或执行本机数据库迁移。
- GitHub 推送在用户明确要求更新时执行。

## 范围边界

本次新增方向分支与持久布局；不新增部门、直属上级、权限继承、拖拽移动、批量导入或布局删除功能。
